# Delegation and continuity

## Delegate for value

Continue in the informed task by default. Delegate only when a bounded result can proceed without steering and its expected decision value, coverage, speed, or independence exceeds the cost of transferring and reintegrating context. Project instructions and the user's request govern whether delegation is available.

Good uses include independent research lanes, bounded specialist analysis, and fresh read-only assurance at a material gate. Routine implementation, same-candidate correction, and shared-context follow-ups normally stay with the informed owner.

A separate user-visible task is for durable user ownership, a distinct authority boundary, or later independent continuation. It is not the default internal work packet.

- Keep one writer per target.
- A delegated writer uses an isolated worktree and an explicit file boundary.
- Other delegates remain read-only.
- The root retains authority, integrates results, resolves conflicts, and verifies the final candidate.
- Respect project concurrency and resource limits. Never run overlapping heavy local gates.

## Transfer the smallest sufficient contract

Give a delegate:

- exact objective and original acceptance anchor;
- pinned project, comparison basis, and candidate identity;
- settled decisions and rejected interpretations;
- authorized actions and explicit boundaries;
- primary evidence needed to decide;
- checks allowed; and
- required return shape.

Prefer a narrow or no-history fork when the full conversation will not change the result. Do not include the desired verdict in an assurance assignment.

The delegate returns the answer or artifact, decisive evidence, affected unverified or conflicted claims, and exact next action. The root checks it against request fidelity, authority, language and format, candidate identity, and decisive evidence. Do not relay an adjacent answer or unsupported closure.

## Preserve continuity across phases

At a material phase transition, choose the least lossy option:

1. continue when the next phase needs current reasoning or evidence and still fits safely;
2. start fresh when the next input is self-contained and prior context is irrelevant;
3. delegate when a bounded independent result can be joined back into the informed task;
4. create a portable handoff when work must move to another harness, repository, worktree, person, or separately owned task; or
5. compact for one named next phase, preserving only what it needs.

Do not clear or compact mid-phase merely for tidiness. Context transitions are informational and never expand authority. Handoffs and summaries are secondary sources, so retain links to decisive primary evidence and preserve reasoning that the next owner must evaluate.

Before releasing, replacing, or handing off a task or worktree containing a needed candidate, establish an artifact checkpoint: exact commit, tree, or durable patch identity; location; verification result; owner; persistence expectation; rollback; and next authorized effect. If durable preservation is not authorized, keep the informed workspace alive and do not call it handoff-ready.
