# Project Operations health

Read [health and cadence](../../references/health-and-cadence.md), [source authority](../../references/source-authority.md), and [PM records](../../references/pm-records.md).

1. Fix the reporting period, prior comparison point, audience, and decision needed.
2. Refresh only evidence required by configured health dimensions.
3. Separate meaningful changes from unchanged activity.
4. Apply project tolerances; explain every Yellow/Red threshold and every Gray evidence gap.
5. Report outcomes and accepted deliverables before activity counts.
6. Include scope/budget/schedule/capacity, delivery/quality, RAID, commitments, decisions, next plan, and freshness.
7. Create an immutable dated health snapshot and compile `current.md` to the concise present orientation.
8. Derive a filtered client version from the same record; draft only unless sending is approved.

Never mark missing data Green, present historical reports as current truth, or expose internal commercial/sensitive details in a client version.
