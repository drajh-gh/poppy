# Project Operations health

Read [health and cadence](../../references/health-and-cadence.md), [source authority](../../references/source-authority.md), [operational controls](../../references/operational-controls.md), [PM records](../../references/pm-records.md), and [project memory lifecycle](../../references/project-memory-lifecycle.md).

1. Fix the reporting period, prior comparison point, audience, and decision needed.
2. Refresh only evidence required by configured health dimensions.
3. Separate meaningful changes from unchanged activity.
4. Apply project tolerances; explain every Yellow/Red threshold and every Gray evidence gap.
5. Report outcomes and accepted deliverables before activity counts.
6. Include scope/budget/schedule/capacity, delivery/quality, RAID, commitments, decisions, next plan, and freshness.
7. Put state and decision first in a bounded executive body; map every included material claim to the dated health snapshot as its evidence appendix. Create the snapshot and compile `current.md` to the present orientation. Keep `current.md` below 750 words and move historical narrative to dated snapshots or canonical history pages.
8. Derive a sensitivity-filtered client version from the same record; draft only unless sending is approved. Validate a normalized operational-control packet when the report depends on multiple refreshed sources, expiring human authority, or a release tuple.

Never mark missing data Green, present historical reports as current truth, or expose internal commercial/sensitive details in a client version.
